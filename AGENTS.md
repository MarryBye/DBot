# AGENTS.md — Архитектура и План разработки бота (DBot)

## 👑 Золотые правила проекта (Непререкаемые стандарты)

1. **Строгое согласование зависимостей:** При надобности в любых дополнительных библиотеках или npm-пакетах — **перед установкой обязательно сообщается пользователю** (зачем нужна библиотека, какие альтернативы), а пользователь принимает решение: ставим или делаем из того, что уже есть. Самовольная установка запрещена.
2. **Мульти-серверная работа:** Бот разрешён к работе на **всех серверах**, на которые он приглашён (глобальная регистрация слэш-команд, префикс `+` и веб-панель с автоопределением и переключением серверов). Очереди, настройки ролей и саундборды изолированы по `guild_id`.
3. **Дуальный командный интерфейс:** Каждая команда реализуется в двух вариантах:
   - Слэш-команда (`/`) с подробным описанием самой команды и каждого аргумента.
   - Классическая команда с префиксом (`+` по умолчанию) с парсингом позиционных аргументов.
4. **Кроссплатформенность источников музыки:** Поддержка YouTube, Spotify и SoundCloud (поиск по названию, треки, плейлисты, альбомы).
5. **Управление через чат и Web-интерфейс:** Любое действие с очередью, воспроизведением, громкостью и саундбордом доступно синхронно как из Discord, так и из Web-панели управления.
6. **Мульти-канальная архитектура:** 5 голосовых воркеров работают независимо, позволяя разным группам людей слушать свою музыку в разных голосовых каналах одного сервера.

## 🎨 Стандарты и Архитектура Web-приложения (Обязательные правила)

Все правила ниже являются **непререкаемыми** при разработке и редизайне веб-интерфейса:

1. **UI-стек:** Используем **Tailwind CSS** + **shadcn/ui** (на базе React + TypeScript + Vite).
2. **Атомарная система примитивных компонентов (Single Source of Truth):**
   - Создаём собственный единый дизайн для всех примитивных UI-компонентов (кнопки, поля ввода, карточки, бейджи, слайдеры, табы, переключатели, модальные окна и т.д.).
   - Все более сложные (составные) компоненты собираются строго из этих примитивов.
   - Изменение примитивного компонента в одном месте должно автоматически обновлять его во всём приложении.
3. **Обязательная декомпозиция (Правило «2+ раз»):**
   - Любой элемент или блок интерфейса, который повторяется в коде **2 и более раз**, обязательно выносится в отдельный переиспользуемый компонент.
4. **Архитектура «Тупые компоненты и сигналы» (Непререкаемое правило):**
   - Все UI-компоненты являются «тупыми» (презентационными): они не содержат бизнес-логики, сетевых запросов и прямого управления состоянием приложения.
   - Компоненты получают данные через пропсы и отдают наружу **только сигналы (коллбэки/события)** о том, что действие произошло (например, `onPlay`, `onSelect`, `onRemove`).
   - Вся логика, обработка API/SSE и привязка реальных действий к этим сигналам пишется исключительно на уровне контейнеров/страниц, где используются компоненты.
5. **Запрет на эмодзи — только иконки `lucide` как компоненты:**
   - Не использовать эмодзи в интерфейсе нигде, если пользователь явно не попросил об этом.
   - Для оформления кнопок, статусов и текста использовать иконки из пакета `lucide` (`lucide-react`), оформленные как отдельный переиспользуемый UI-компонент (единая обёртка для контроля размеров, толщины линий и цветов).
6. **Стиль Metro Design (Бизнес-минимализм):**
   - Дизайн строго следует принципам **Metro Design**: чёткая сетка, плоские поверхности (flat), чистая типографика, максимальная ясность и функциональность в духе деловых/бизнес-приложений.
   - **Запрет на «типичный нейросетевой дизайн»:** никаких декоративных градиентов, неона, glassmorphism и лишних визуальных эффектов.
7. **Чистота текстов (Без дебага и лишней воды):**
   - Запрещено выводить на сайте любой отладочный текст, номера портов, технические детали, внутренние идентификаторы или лишние пояснения.
   - Все подписи и инструкции — максимально короткие, понятные, простым языком. На экране только то, что реально нужно пользователю.
8. **Интернационализация (i18n) на кодах текстов:**
   - Стартовые языки: **английский (`en`)**, **украинский (`uk`)** и **русский (`ru`)**.
   - Весь отображаемый текст в интерфейсе задаётся строго строковыми кодами (ключами) — никакого захардкоженного текста в компонентах.
   - Реализуется собственная библиотека/модуль локализации, возвращающая текст по коду для активного языка.
   - Логика выбора языка: по умолчанию определяется язык системы/браузера; при явном выборе пользователем язык сохраняется в `localStorage` и в дальнейшем читается оттуда.
   - Переводится весь интерфейс, за исключением ключевых неизменяемых сущностей (название бота `DBot`, имена пользователей, названия треков, серверов и каналов).
9. **Темы оформления (Светлая по умолчанию + Тёмная):**
   - **Светлая тема (Light Mode)** используется по умолчанию.
   - Обязателен переключатель на **тёмную тему (Dark Mode)** с сохранением выбора пользователя.
   - Реализуется архитектурно централизованно через семантические дизайн-токены (CSS-переменные + класс `.dark`), чтобы каждый примитив и составной компонент автоматически поддерживал обе темы без дублирования стилей.
10. **Адаптивность под мобильные устройства:**
    - Вся разметка, навигация, плеер, очередь и саундборд обязаны корректно адаптироваться под экраны мобильных устройств и планшетов.
11. **Согласование пакетов:** Как и во всём проекте (Золотое правило №1), любые новые npm-пакеты устанавливаются строго после объяснения их назначения и явного одобрения пользователя.
12. **Обязательная пагинация динамических списков:** Везде, где ожидается неопределённое или растущее количество элементов (очередь треков на главной, очередь агента, результаты поиска, плейлисты, треки внутри плейлиста, сетки саундборда и т.д.), обязательно используется единый переиспользуемый примитив пагинации (`<Pagination />`).

## 📌 Обзор проекта
Персональный многофункциональный Discord-бот для кентовки с закрытым контуром безопасности (изоляция одной гильдии/канала).
Основные компоненты:
1. **Музыкальная система** с поддержкой очередей, плейлистов, регулятора громкости и кроссплатформенных источников (YouTube, SoundCloud, Spotify и др.).
2. **Саундборд** (быстрое воспроизведение звуковых эффектов и локальных мемов).
3. **Мульти-канальная архитектура (Worker Clones)** для одновременного воспроизведения в разных голосовых каналах.
4. **Web-панель управления** с авторизацией через Discord OAuth2, настройкой ролевого доступа админами и управлением очередью/саундбордом в реальном времени.

## ❓ Ответ на вопрос: подключение бота в несколько голосовых каналов одновременно

> **Ключевое ограничение протокола Discord:**
> Согласно архитектуре Discord Gateway, одна учетная запись бота (один токен/пользователь) физически может находиться **только в одном голосовом канале в рамках одного сервера одновременно**. Если бот переходит в канал B, Discord автоматически отключает его от канала A.

### 💡 Решение (Паттерн "Worker Clones / Радио-боты"):
Для работы на разные группы людей в одном сервере используется проверенная архитектура сателлитов:
1. Создаются дополнительные приложения в Discord Developer Portal (например, `DBot #1`, `DBot #2` или `DBot - Клубничка`, `DBot - Лаундж`).
2. Все эти боты подключаются к **одному общему бэкенду и базе данных**.
3. Основной бот (или веб-панель) распределяет каналы:
   - Группа 1 в «Голосовом 1» включает трек -> подключается Worker 1.
   - Группа 2 в «Голосовом 2» включает трек -> подключается Worker 2.
4. В коде это реализуется как пул голосовых инстансов (`VoicePoolManager`), где каждый воркер имеет свой токен и независимый аудиоплеер.

## 🛠️ Технологический стек

- **Backend & Core:** Node.js (v24), TypeScript, `discord.js` (v14).
- **Командный интерфейс:** Дуальный вызов — слэш-команды (`/`) + классические префиксные команды (`+` по умолчанию из `.env`).
- **Voice Engine:** `@discordjs/voice`, `libsodium-wrappers`, `@discordjs/opus` / `opusscript`, `ffmpeg-static`.
- **Audio Extractors:** `play-dl` / `@distube/ytdl-core` / `soundcloud-scraper` (обеспечивают поток и парсинг метаданных треков YouTube, SoundCloud, Spotify).
- **Database:** SQLite (`better-sqlite3`), Drizzle ORM, Drizzle Kit.
- **Web Backend & Realtime:** Fastify / Express + `ws` (WebSockets для синхронизации очереди и громкости в реальном времени).
- **Auth:** Discord OAuth2 (получение токена, профиля и гильдейских ролей пользователя).
- **Web Frontend:** Vite + React + TypeScript + Tailwind CSS + shadcn/ui + Lucide Icons (Metro Design, светлая тема по умолчанию + переключатель на тёмную, адаптивная вёрстка, i18n EN/UK/RU).

## ☁️ Особенности развертывания на Oracle Cloud (Free Tier)
1. **Единый Node.js процесс:**
   - Основной координатор, все 5 голосовых агентов и встроенный Web-сервер (`node:http` + SSE) работают внутри одного процесса без лишних зависимостей.
   - Потребление оперативной памяти в режиме ожидания: ~80-120 МБ RAM, под нагрузкой: ~200-350 МБ RAM. Это гарантированно укладывается даже в минимальный инстанс `VM.Standard.E2.1.Micro` (1 ГБ RAM) или ARM Ampere (24 ГБ RAM).
2. **Аудио-кодеки:**
   - Используется `opusscript` и `ffmpeg-static`, что исключает проблемы с нативной сборкой на ARM64 / Ubuntu.
3. **Автозапуск (Systemd):**
   - На сервере процесс управляется через `pm2` или `systemd`, обеспечивая автоматический перезапуск при сбоях.

### Фаза 5: Web Backend и Ролевая система
- [x] Таблицы в SQLite:
  - `web_sessions` — сессии пользователей.
  - `dashboard_settings` — минимальная роль для доступа к плееру, админские роли.
  - `sounds` — метаданные загруженных звуков.
- [x] Сервер API (чистый `node:http` без лишних зависимостей):
  - Авторизация через Discord OAuth2 (`/api/auth/discord` + `/api/auth/callback`) И мгновенный вход по одноразовой ссылке `/web` (`+web`).
  - Проверка членства в гильдии, наличия настроенной роли и **нахождения в голосовом канале**.
  - Привязка всех действий пользователя строго к агенту его голосового канала.
  - Роуты очереди (`/api/queue/remove`, `/api/queue/move`, `/api/queue/clear`).
  - Роуты плеера (`/api/player/play`, `pause`, `resume`, `volume`, `skip`, `stop`, `shuffle`, `loop`).
  - Роуты саундборда (`/api/soundboard/custom`, `upload`, `memes`, `save-meme`, `play`, `file/:id`).
- [x] Real-time синхронизация через Server-Sent Events (`/api/events`):
  - Мгновенное обновление статуса войса, трека, очереди, громкости, агентов и библиотеки звуков.

### Фаза 6: Web-панель (Frontend)
- [x] Модульный SPA-интерфейс на React + TypeScript + Vite + Tailwind CSS + shadcn/ui + Lucide (`web/` -> сборка в `public/`):
  - Metro Design: плоская деловая эстетика, светлая тема по умолчанию + переключатель на тёмную (CSS-токены).
  - Атомарная система примитивных компонентов (`web/src/components/ui/`) и архитектура «тупые компоненты + сигналы» (`web/src/components/blocks/`, `web/src/containers/`).
  - Интернационализация (`en`, `uk`, `ru`) через строковые коды (`web/src/i18n/`) с автоопределением системного языка и сохранением выбора в `localStorage`.
  - Авторизация через Discord OAuth2 или команду `/web`, переключение серверов, живой статус голосового канала.
  - Плеер, очередь с drag-and-drop, личные плейлисты, саундборд («Звуки сервера» + «Мемы» MyInstants), статус голосовых агентов и настройки доступа/cookies для администраторов.
  - Отдельный запуск UI без бота через Vite (`pnpm web:dev`) и режим работы с живым ботом (`pnpm web:dev:live`).
