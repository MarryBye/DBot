# AGENTS.md — Архитектура и План разработки бота (DBot)

## 👑 Золотые правила проекта (Непререкаемые стандарты)

1. **Строгое согласование зависимостей:** При надобности в любых дополнительных библиотеках или npm-пакетах — **перед установкой обязательно сообщается пользователю** (зачем нужна библиотека, какие альтернативы), а пользователь принимает решение: ставим или делаем из того, что уже есть. Самовольная установка запрещена.
2. **Мульти-серверная работа:** Бот разрешён к работе на **всех серверах**, на которые он приглашён (глобальная регистрация слэш-команд, префикс `+` и веб-панель с автоопределением и переключением серверов). Очереди, настройки ролей и саундборды изолированы по `guild_id`.
3. **Дуальный командный интерфейс:** Каждая команда реализуется в двух вариантах:
   - Слэш-команда (`/`) с подробным описанием самой команды и каждого аргумента.
   - Классическая команда с префиксом (`+` по умолчанию) с парсингом позиционных аргументов.
4. **Кроссплатформенность источников музыки:** Поддержка YouTube, Spotify и SoundCloud (поиск по названию, треки, плейлисты, альбомы).
5. **Управление через чат и Web-интерфейс:** Любое действие с очередью, воспроизведением, громкостью и саундбордом доступно синхронно как из Discord, так и из Web-панели управления.
6. **Мульти-канальная архитектура:** 5 голосовых воркеров работают независимо, позволяя разным группам людей слушать свою музыку в разных голосовых каналах одного сервера.

## 📌 Обзор проекта
Персональный многофункциональный Discord-бот для кентовки с закрытым контуром безопасности (изоляция одной гильдии/канала).
Основные компоненты:
1. **Музыкальная система** с поддержкой очередей, плейлистов, регулятора громкости и кроссплатформенных источников (YouTube, SoundCloud, Spotify и др.).
2. **Саундборд** (быстрое воспроизведение звуковых эффектов и локальных мемов).
3. **Мульти-канальная архитектура (Worker Clones)** для одновременного воспроизведения в разных голосовых каналах.
4. **Web-панель управления** с авторизацией через Discord OAuth2, настройкой ролевого доступа админами и управлением очередью/саундбордом в реальном времени.

## ❓ Ответ на вопрос: подключение бота в несколько голосовых каналов одновременно

> **Ключевое ограничение протокола Discord:**
> Согласно архитектуре Discord Gateway, одна учетная запись бота (один токен/пользователь) физически может находиться **только в одном голосовом канале в рамках одного сервера одновременно**. Если бот переходит в канал B, Discord автоматически отключает его от канала A.

### 💡 Решение (Паттерн "Worker Clones / Радио-боты"):
Для работы на разные группы людей в одном сервере используется проверенная архитектура сателлитов:
1. Создаются дополнительные приложения в Discord Developer Portal (например, `DBot #1`, `DBot #2` или `DBot - Клубничка`, `DBot - Лаундж`).
2. Все эти боты подключаются к **одному общему бэкенду и базе данных**.
3. Основной бот (или веб-панель) распределяет каналы:
   - Группа 1 в «Голосовом 1» включает трек -> подключается Worker 1.
   - Группа 2 в «Голосовом 2» включает трек -> подключается Worker 2.
4. В коде это реализуется как пул голосовых инстансов (`VoicePoolManager`), где каждый воркер имеет свой токен и независимый аудиоплеер.

## 🛠️ Технологический стек

- **Backend & Core:** Node.js (v24), TypeScript, `discord.js` (v14).
- **Командный интерфейс:** Дуальный вызов — слэш-команды (`/`) + классические префиксные команды (`+` по умолчанию из `.env`).
- **Voice Engine:** `@discordjs/voice`, `libsodium-wrappers`, `@discordjs/opus` / `opusscript`, `ffmpeg-static`.
- **Audio Extractors:** `play-dl` / `@distube/ytdl-core` / `soundcloud-scraper` (обеспечивают поток и парсинг метаданных треков YouTube, SoundCloud, Spotify).
- **Database:** SQLite (`better-sqlite3`), Drizzle ORM, Drizzle Kit.
- **Web Backend & Realtime:** Fastify / Express + `ws` (WebSockets для синхронизации очереди и громкости в реальном времени).
- **Auth:** Discord OAuth2 (получение токена, профиля и гильдейских ролей пользователя).
- **Web Frontend:** Vite + React + Tailwind CSS (современный dark-mode интерфейс, плеер, drag-and-drop треклист, сетка кнопок саундборда).

## ☁️ Особенности развертывания на Oracle Cloud (Free Tier)
1. **Единый Node.js процесс:**
   - Основной координатор, все 5 голосовых агентов и встроенный Web-сервер (`node:http` + SSE) работают внутри одного процесса без лишних зависимостей.
   - Потребление оперативной памяти в режиме ожидания: ~80-120 МБ RAM, под нагрузкой: ~200-350 МБ RAM. Это гарантированно укладывается даже в минимальный инстанс `VM.Standard.E2.1.Micro` (1 ГБ RAM) или ARM Ampere (24 ГБ RAM).
2. **Аудио-кодеки:**
   - Используется `opusscript` и `ffmpeg-static`, что исключает проблемы с нативной сборкой на ARM64 / Ubuntu.
3. **Автозапуск (Systemd):**
   - На сервере процесс управляется через `pm2` или `systemd`, обеспечивая автоматический перезапуск при сбоях.

### Фаза 5: Web Backend и Ролевая система
- [x] Таблицы в SQLite:
  - `web_sessions` — сессии пользователей.
  - `dashboard_settings` — минимальная роль для доступа к плееру, админские роли.
  - `sounds` — метаданные загруженных звуков.

  - Привязка всех действий пользователя строго к агенту его голосового канала.
  - Роуты очереди (`/api/queue/remove`, `/api/queue/move`, `/api/queue/clear`).
  - Роуты плеера (`/api/player/play`, `pause`, `resume`, `volume`, `skip`, `stop`, `shuffle`, `loop`).

- [x] Real-time синхронизация через Server-Sent Events (`/api/events`):
  - Мгновенное обновление статуса войса, трека, очереди, громкости, агентов и библиотеки звуков.
